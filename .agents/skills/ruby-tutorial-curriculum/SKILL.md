# Ruby tutorial curriculum

Inspect the current catalog, lesson associations, ordering resolver and navigation. Apply [placement decisions](references/placement.md), not a memorized chapter list. Keep learning classification/order, official reference classification and runtime availability distinct.

State the learner outcome, prerequisites, included/excluded scope and next stage. Decide existing placement, new chapter, split/merge or deferral from that evidence. Do not use Other/Supplementary as a container for unclassified topics. Version addition alone is not grounds for a chapter.

For a planning request, deliver placement rationale, affected identities/URLs and unresolved conditions. If reorganization is authorized, implement its catalog/association/ordering/successor changes and verify prerequisite reachability, actual navigation order and availability across versions. Do not expand a placement decision into wholesale lesson rewriting.

Use [data discovery](../ruby-tutorial-authoring/references/data-contract.md) before edits and [source standards](../ruby-tutorial-authoring/references/sources.md) for evidence. Pass agreed goals, placement, prerequisites and URL decisions to [authoring](../ruby-tutorial-authoring/SKILL.md) when lesson edits are needed. Use [versioning](../ruby-tutorial-versioning/SKILL.md) only when release support changes. For quality review consult [the shared rubric](../ruby-tutorial-review/references/evaluation.md).

Report decisions, source changes if authorized, checks and uncertainties. Respect publication scope; do not treat this skill as permission to publish. Do not rewrite resolved decisions or repeat another responsibility's checks without a new reason.
