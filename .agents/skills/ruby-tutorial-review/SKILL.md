# Ruby tutorial review

Use [the evaluation rubric](references/evaluation.md). Inspect the target and source evidence; report location, observed behavior, consequence and smallest correction. Separate confirmed defects, improvements and missing evidence. A successful validator, build or output comparison does not establish teaching quality.

This responsibility is read-only: do not modify lessons, product code, tests or skill files. Temporary isolated diagnostics and saved reports are permitted within the user's scope; distinguish those artifacts from target edits. External posting requires authorization. Do not fix findings merely because they are easy.

Use [placement criteria](../ruby-tutorial-curriculum/references/placement.md), [data discovery](../ruby-tutorial-authoring/references/data-contract.md), [source standards](../ruby-tutorial-authoring/references/sources.md) and [release checks](../ruby-tutorial-versioning/references/release-process.md) as relevant. Do not require all other skills for every review.

For an explicitly authorized review-and-fix request, first identify findings, then state the transition to the appropriate editing responsibility. Where reviewer and implementer are separate sessions, deliver feedback to the implementer and remain read-only. Hand off evidence and verification gaps, not permission inferred from this skill. Preserve user-requested session retention.
