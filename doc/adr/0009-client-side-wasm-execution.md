# ADR-0009: コード実行はクライアント側 (ruby.wasm) で行う

## Status

Accepted (2026-08-22)

## Context

この playground は visitor自身も共有されたsnippetを実行できる (ADR-0008の方向転換時に確認済み) ため、不特定多数が任意のRubyコードを実行できることになる。実行をどこで行うかで、安全性要件の重さが根本的に変わる。

- **サーバー側実行**: 不特定多数がサーバー上で任意コードを実行できてしまう以上、コンテナ隔離・リソース制限・ネットワーク遮断・DoS対策が避けられない、最重量級の技術課題になる
- **クライアント側実行**: `ruby.wasm` という、CRubyをWebAssemblyにコンパイルしてブラウザの中でRubyをそのまま動かせる公式プロジェクトが存在する。visitorが実行するコードは自分のブラウザの中だけで完結し、サーバーには一切送られない

## Decision

コード実行はクライアント側、`ruby.wasm` を用いてブラウザ内で行う。サーバー側には任意コード実行のための隔離基盤 (コンテナ・sandbox) を持たない。

## Consequences

- サーバー側の重量級sandbox基盤 (コンテナオーケストレーション、リソース制限、DoS対策) が不要になる
- 標準gem以外の外部ライブラリを使うコードは実行できない制約が生まれる (このplaygroundの主目的である「Ruby言語そのものを試す」スコープでは許容範囲と判断)
- ブラウザ内で完結するため、暴走コード (無限ループ等) への対策はサーバーではなくブラウザタブ側の対策 (ADR-0010参照) に責務が移る
