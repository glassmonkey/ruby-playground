# ADR-0016: ローカル完成ラインはSnippet管理 (ADR-0012) まで

## Status

Accepted (2026-08-24)

## Context

[ADR-0013](0013-mvp-scope.md) でMVPの範囲を「エディタ + ruby.wasm実行 + URL即席共有」と決めた。このMVPは既に達成済みである。

- #5 URL即席共有 → PR #18 マージ済み ([ADR-0011](0011-url-based-sharing.md))
- #10 エラー出力の視覚的区別 → PR #19 マージ済み
- #11 全体レイアウト → PR #21 マージ済み
- #16 所有者用ログイン → PR #20 マージ済み。ADR-0013 が「含まない (post-MVP)」に挙げていた認証が先行してマージされている

一方でbacklogには、Snippet CRUD (#17)、エディタ置き換え (#9)、コード補完 (#29)、Cloudflare本番ホスティング (#7 / #14 / #15) が並んでいる。ADR-0013 は「MVPに含まないもの」を列挙したが、**post-MVPのどこまでを一区切りとするか** は決めていなかった。そのため「次に何を着手すべきか」を判断するたびに、毎回スコープ議論をやり直す状態になっていた。

## Decision

当面のゴールを「ローカル環境で動くところまで」とし、その完成ラインを **Snippet管理 ([ADR-0012](0012-snippet-management-in-rails.md) / #17) まで** とする。

**含む**:
- #28 ログアウトUI導線 (#16 で入った認証の未完部分)
- #17 Snippetの保存・一覧・編集・削除 (ADR-0012)

**含まない**:
- #9 エディタをMonaco/CodeMirrorに置き換える
- #29 コード補完 (能力調査と論点整理は先行させるが、実装判断は完成ライン到達後)
- #7 / #14 / #15 Cloudflare本番ホスティングとそのCI自動化

**完成ラインの条件ではないが、並行して進めてよいもの**:
- #23 frontend/ のTypeScript化、#24 frontend/ のテスト追加 (いずれも内部品質で、エンドユーザーには不可視)

この線を引いた理由:

- ADR-0013 が「post-MVPの段階からRailsの本領 (DB, 認証, CRUD) が活きてくる」と書いている。#17 を入れないと、Railsアプリとしての形が揃わないまま止まる
- #16 が既にマージ済みで、#17 の前提条件 (所有者のみが管理できること) は満たされている
- #9 と #29 はいずれもseverity Lowで工数が大きい。完成ラインに入れると所要が倍以上になる割に、得られるのは体験の改善であって機能の完成ではない
- #14 の本文にある通り、Cloudflare系はローカル開発をブロックしていない。外部公開したくなった時点で着手すればよい

## Consequences

- #7 / #14 / #15 は「実際に外部公開したくなったタイミング」までbacklogに置く
- #9 は Rails側の view/CSS と `frontend/src/` の両方に触れるため、他の作業と並行させると衝突する。完成ライン到達後に単独で着手する
- #29 は能力調査と論点整理までを先行させ、実装するかどうかの判断は完成ライン到達後に行う ([ADR-0015](0015-completion-spike-result.md) で前回のspikeがfail判定になっているため、判断材料を先に揃える)
- 完成ライン到達後に次の区切りをどこに置くかは、この ADR ではなく別 ADR で改めて決める
