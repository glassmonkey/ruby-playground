# ADR-0007: MVPスコープ — tool呼び出し無しの純粋chat

## Status

Accepted (2026-08-22)

## Context

agent hostingサービスとして最終的に持ちたい機能 (tool連携、トークン節約、モニタリング等) を最初から全て作ると初期実装量が大きくなる。「chatGPTライクに会話できる」ことを最初のMVPスコープとする案が出た。

「chatGPTライク」の解釈として、tool呼び出し (web検索等) を含むかどうかが論点になったが、tool呼び出しも一旦落とす、という確認を得た。

## Decision

MVPのスコープを「tool呼び出しを含まない、純粋なテキストchat」に限定する。以下は後回しとする:

- **論点D**: トークン節約のためのコンテキスト圧縮方式
- **論点E**: 最初にサポートするtool範囲、tool実行権限管理
- **論点F**: 使用量モニタリングダッシュボードの構築方式
- trace・失敗切り分けの体系化 (最低限のエラー表示のみ用意する)

## Consequences

- [ADR-0003](0003-async-execution.md) で非同期実行を決めた根拠のうち「重いtool呼び出しで数十秒〜分かかる」は弱まるが、モバイル回線の不安定さへの対処という理由は引き続き有効なため、非同期実行の方針自体は変更しない
- [ADR-0004](0004-conversation-turn-step-model.md) のStepテーブルはMVPでは常に空になる
- [ADR-0006](0006-agent-definition-schema.md) の通り、Agent定義がシンプルなカラム構成で済むようになった
- post-MVPで論点D/E/Fに戻って設計判断を行う必要がある
