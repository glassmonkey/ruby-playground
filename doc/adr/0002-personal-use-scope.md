# ADR-0002: 個人利用スコープ

## Status

Superseded by [ADR-0008](0008-pivot-to-ruby-playground.md) (2026-08-22)

## Context

外部向けmulti-tenant SaaSとして作るか、自分/社内用として作るかで、認可・課金・テナント分離の設計の重さが大きく変わる。

- multi-tenant SaaS: テナント分離・認可・不正利用対策・billing連携が最初から必須級になり、初期実装量が増える
- 個人/社内用: 認可は「自分かどうか」レベルで済み、billingも自分のLLM API使用量を把握できれば十分

ただし「スマホ利用など場所を問わず使いたい」という要件があり、単純なlocalhost運用では済まない。インターネット経由でどこからでもアクセスできる必要があり、誰でも叩ける URL に上げる以上、自分専用のログイン認証は省略できない。

## Decision

自分専用の利用に絞る。インターネット経由でアクセス可能な形でホスティングし、Rails標準の認証機能で自分専用ログインを実装する。Tenant/Membershipのような多人数の権限構造は持たない。

## Consequences

- 認可はRails標準の単一ユーザー認証で足りる
- 課金・plan制限のロジックは持たない (自分のLLM API keyの使用量を把握できれば十分。BYOK/自社持ちの区別も実質不要になった)
- 将来外部に開放したくなった場合は、テナント境界・課金を後付けする手戻りが発生する (現時点では許容する)
