# ADR-0012: Snippet管理はRailsで行う。閲覧はログイン不要、管理は所有者のみ

## Status

Accepted (2026-08-22)

## Context

「共有・管理」のうち、「管理」(保存したsnippetを後から見返す・整理する) をどう実現するか検討した。候補は次の2つ:

- **Rails + DB**: 自分のアカウントに紐づけてSnippetを保存し、一覧・閲覧をRailsの画面で提供する
- **localStorageのみ**: サーバー不要でもっと単純だが、別のデバイス/ブラウザからは保存済みSnippetが見れない。参考実装 (php-playground) はこちら側 (というより管理機能自体を持たない)

当初、旧ADR-0002 (agent hosting時代の「どこからでもアクセスしたい」要件) を根拠にRails+DB案を推した。しかしこの要件はagent hosting (チャットをスマホから使いたい) の文脈で出たものであり、今回のsnippet管理にそのまま当てはまる根拠にはならないという指摘を受け、この論拠は撤回した。

改めて確認した結果、「snippet管理という意味でRailsの機能を使いたい」という意向が確認された。管理の範囲は「基本的に自分の管理」(他人のsnippetを閲覧できるギャラリー機能は不要)。ただし、保存したsnippetはURLセーフな識別子を持ち、ログインなしでも閲覧できることを想定している。

## Decision

Snippetの管理 (作成・編集・削除・一覧) はRails + DBで行う。

- 所有者は自分1人 (旧ADR-0002と同様、multi-tenantなギャラリー機能は持たない)
- 作成・編集・削除には認証が必要 (Rails標準の認証機能を利用)
- 保存済みSnippetの閲覧は、URL (識別子) を知っていれば誰でも認証なしで可能
- 公開範囲は単一 (「保存すればURL経由で閲覧可能」) とし、public/private/unlistedのような複雑な可視性区分は持たない。下書きを隠す必要が生じた場合は、後から `private` フラグを1個追加するだけで対応できるため、現時点では決め打ちしない

## Consequences

- Snippetモデルは所有者(User)に belongs_to する。認可は「自分の所有物か」の1軸で足りる、複雑な認可ロジックは不要
- 閲覧経路の認証を作らんで済む分、実装がシンプルになる
- 「即席共有 (ADR-0011, URLエンコード)」と「管理された保存済みSnippet (本ADR, DB + URL識別子)」の2つの共有経路が併存する。ユーザー体験上、両者の関係 (即席共有からワンクリックで保存できる、等) は実装時に検討する
